Using your own domain is part of the paid plans. You keep your domain where it is; you only add a few DNS
records at your DNS provider (often the company you bought the domain from).

## Before you start

- You need to be able to edit DNS records for the domain.
- If mail already arrives somewhere else for this domain, it moves to AnhourMail once the inbound record below
  is in place. Plan the switch for a quiet moment.

**Required** records are needed before the domain works. **Recommended** records make mail apps set themselves

### DKIM keys

DKIM lets receivers check that mail from your domain really came from AnhourMail. Your domain gets its own two
signing keys (one RSA, one Ed25519), and you publish each as a **TXT** record. The keys are created once the
ownership and MX records are found, so the console shows a placeholder until then: add the other records, press
**Check now**, and the two DKIM records appear within a minute with their exact names (like
`v1-rsa-20261028._domainkey`) and values. Copy each value whole; it is long, and some DNS providers split it into
several quoted parts, which is fine.

## How long does it take?

DNS changes usually show up within minutes, but some providers take a few hours. The console re-checks a new
domain every few minutes for its first week, and you can press **Check now** at any time. Each record shows
**Found**, **Missing**, **Different value** (with what we found instead) or **Couldn't check** (try again shortly).

Once the required records are found, the domain shows **Setting up** for a minute or two, then **Active**.

## Common problems

- **The name already has a value.** Some providers add the domain for you. If the name field shows your domain
  already, enter only the part before it.
- **There is already an SPF record.** A domain can have only one. Merge ours into the existing one instead of
  adding a second.
- **"DKIM not found in DNS — mail will fail DKIM."** The TXT record for that key isn't there yet. Check the name
  (only the part before your domain, if your provider adds the domain itself) and that the value was pasted whole.
- **"The DKIM key in DNS is not this one."** Something else is published at that name, often an older key. Replace
  the value with the one shown in the console.
- **You connected your domain before October 28, 2026.** Earlier setups used DKIM CNAME records. Delete those
  (`am1._domainkey` and `am2._domainkey`) and add the TXT records the console shows now.
- **Verification is still pending after a day.** Make sure there is no typo in the verification code, then press
  **Check now**.

## How long a domain can stay unverified

A domain that isn't verified in time is removed from your account, so an unfinished setup never holds a domain for
good:

- **Ownership and MX records found:** verify within <Value of="pendingDomainSetupDays" /> days of adding the domain,
  and keep those records in place meanwhile. We check them daily; if either is gone, the domain is removed.
- **Otherwise:** an unverified domain is removed after <Value of="pendingDomainDays" /> days.

Removed domains show in your [audit log](/docs/audit-log). Add the domain again to start over (it gets a new
verification code).

## Removing a domain

Open the domain from the **Domains** list, go to its **Overview** tab and choose **Remove domain…**. Remove or move its mailboxes and aliases first; the console tells
you if any still use it. You can add the domain again later.

## If someone else already added your domain

Adding a domain doesn't claim it: only the account whose verification record is published can make it active. If
the console says the domain is connected to another account and it's yours, contact support.

If **Check now** says your records are found but another account is still connected to the domain, it has an
unfinished setup of its own. Delete any verification TXT record other than the one your console shows, then check
again: once their verification record is gone, their setup is removed and yours goes ahead a few minutes later.
