# Rate limits

Last updated: 2026-10-23 (free platform addresses: `platformAddressCheck*`, `platformMailbox*`, `emailVerification`; sign-in security: `authFactor`, auth endpoint allow-list; webmail tiers and contacts; people and invites). Rule 14: **every endpoint has a rate limit**. Code: `packages/server/src/rate-limit.ts` (tiers) + the `route()` wrapper in `apps/web`. When the code lands, the tier names and numbers there are canonical; this table is updated in the same change.

## How it works

- Redis fixed window (`INCR` + `EXPIRE`), key `am:rl:<tier>:<endpoint>:<caller>:<window>`. Per-account send quotas use a sliding window (sorted set) so a burst at a window edge can't double the limit.
- **Caller:**
  - signed in: `s:<hash of session id>` (or `u:<user id>` for per-user tiers);
  - otherwise `ip:<client ip>`.
  - The client IP comes from `X-Forwarded-For` **only when `TRUST_PROXY=true`**. NGINX overwrites that header in production. Otherwise the socket address is used, which fixes the portal's spoofable limiter (`research/reference-patterns.md` pattern 4).
- Responses carry `RateLimit-Limit`, `RateLimit-Remaining` and `RateLimit-Reset`. Over the limit: **429** `{ error: { code: "rate_limited" } }` + `Retry-After`.
- **Fail mode** per tier:
  - _open_ = a Redis error allows the request (logged at warn);
  - _closed_ = a Redis error returns 503 for that request.
  - Anything that costs money or reputation is fail-closed.
- Buckets are named by method + **route pattern** (`/api/webmail/messages/:emailId`), built from the route's params
  (`routeTemplate` in `apps/web/src/server/http/route.ts`), so varying an id never yields a fresh bucket.
- `/api/health*` is exempt. Better-auth's own per-endpoint limits sit inside the `auth` tier.
- `/api/auth/*` is one catch-all route with an **allow-list** (`apps/web/src/server/auth/endpoints.ts`): each
  better-auth endpoint the console uses has its tier (`auth`, `authFactor` or `sensitive`); everything else answers 404.
  The emailed confirmation link (`GET /api/auth/verify-email`) is `auth`; the public "send verification email"
  endpoint is not exposed (the console's own `POST /api/me/email-verification` sends to the signed-in address only).
- Some routes add a second, per-subject limit inside the handler (`enforceLimit` in `route.ts`: per account, per client
  address), answering 429 `rate_limited` like the route tier; the tier's fail mode applies.

## Adding an endpoint

Pick a tier in `route(handler, { limit: LIMITS.<tier> })`. If none fits, add a tier here and in code in the same change. The RBAC harness checks that each route returns 429 after its limit with the expected headers.
